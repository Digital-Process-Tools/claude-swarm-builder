Issue #28's self-review (second pass, oss:auditor) found: `rule_authority_subset` (R04, in
`scripts/swarm_doctor.py`) builds `eid = edge.get("id", f"{from_name}->{to_name}")` -- when an
edge dict has no `"id"` key, `eid` becomes a synthetic placeholder like `"triager->auditor"`
rather than a real edge id. That same value is now passed as the explicit `edge=` field the
reader's `findingsForEdgeId` treats as a schema-pattern edge id (`^[a-z][a-z0-9-]*\.[0-9]{2,}$`).
No real edge ever carries that synthetic value, so `findingsForEdgeId` never matches it and the
R04 finding silently never renders on the map overlay -- for the one case where an edge is
missing its own required `id` (itself a schema-invalid document R04 does not gate on, unlike
R01-R03's `_shape_problem()` check).

Confirmed: the fallback expression itself predates this issue's diff (unchanged by it), only
newly promoted into the explicit `edge=`/`agent=` kwarg contract without handling the
"no real id" case. Ranked `misreports`, non-blocking, ships fine as-is for now.

Not decided here: whether R04 should gate on `_shape_problem()` the way R01-R03 do (which would
turn this into a `could-not-check` instead of a misleading `edge=` value), whether the synthetic
fallback should be dropped from the `edge=` kwarg specifically (passing `edge=""` instead when
`id` is absent, so the reader correctly shows "no attachment point" rather than a silently-dead
one), or whether this is worth a dedicated fix at all given how narrow the trigger is (an edge
missing its own `id`, which R00's schema check already flags separately). A later curation pass
should pick one.
