R06 (`scripts/swarm_doctor.py::rule_scripts_declared`) checks two directions: every declared
`scripts[].name` must exist under `--root`, and every `*.py`/`*.sh` file under `scripts/` must be
named by some agent. Both comparisons are exact string/filesystem matches, and that is
deliberate after a review round found a case-folding attempt introduced a worse bug (see the
commit history on issues #4/#5/#6) -- but it leaves a real, unfixed platform gap worth recording
for whoever picks R06 up again.

The "exists under --root" half goes through `pathlib.Path.is_file()`, which asks the OS, and the
OS's own filesystem is case-insensitive by default on macOS and Windows and case-sensitive on
Linux. The "is it declared" half compares the actual on-disk filename against the declared-name
set with plain Python string equality, which is always case-sensitive regardless of platform.

So a `swarm.json` that declares `scripts/Foo.py` when the file on disk is actually `scripts/foo.py`
verifies "exists" on macOS/Windows (the OS treats them as the same file) but fails "exists" on
Linux -- while the orphan side always reports `foo.py` as undeclared everywhere, since `Foo.py`
never appears as a string. The net effect: the same `swarm.json` can pass R06 cleanly on two of
this repo's own three CI legs (`.github/workflows/tests.yml` runs `ubuntu-latest`, `macos-latest`,
`windows-latest`) and produce a warning-level finding only on the third.

A real fix would need R06 to do its own case-insensitive directory walk (list the actual
directory contents and compare names case-insensitively, rather than trusting `is_file()`'s
OS-dependent behavior) on both sides consistently -- not a quick patch, and the first attempt at
one (normalizing both sides to lowercase) introduced a filename-normalization bug that also
mangled a legitimate declared path in an unrelated way. Left as `test_r06_case_mismatch_between_
declared_and_disk_is_a_known_platform_gap` in `tests/test_example_validates.py`, which documents
the current (inconsistent) behavior rather than asserting a fixed one, so a future attempt has a
red/green target rather than starting from a description.
