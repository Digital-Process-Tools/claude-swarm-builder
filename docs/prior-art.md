# Prior art

Checked 2026-09-19. Search by what a tool calls itself ("harness as code", "topology"), not by what we call it — two rounds missed AgenTopology that way.


Canvas is commodity. The model underneath mostly exists too, in one place.

- **AgenTopology** (github.com/agentopology/agentopology, npm `agentopology`, Apache-2.0, TypeScript, 103 stars, created 2026-03-11, pushed 2026-08-26, verified) — "harness as code, the Terraform for AI agents." Declarative `.at` DSL: `agent {model, tools, permissions, reads, writes, outputs {typed enums}}`, `flow { a -> b [when a.out == v, max 2] }`, error edges `-x->`, node kinds agent / orchestrator / human / group / action / gate, `schedule` (cron), `hooks`, `tools { script, args }`, `metering { track: [tokens-in, tokens-out, cost, wall-time], per: [agent, run, phase] }`. 93 validators in `spec/validation.md`: V4 agent absent from flow = error (our orphan); **V11 if A writes X and B reads X a path A → B must exist = the #1386 class**; V93 edge with no declared handoff = warning. `import --target claude-code --dir .claude` reverse-engineers `.claude/agents/*.md`, `sync` writes back. Interactive visualizer; `parse / validate / generateVisualization` exported as a library. Compile targets include Claude Code and the Workflow tool, with a full mapping doc (`docs/AT_VS_WORKFLOW_STRATEGY.md`: host drives phases and hooks, Workflow runs one fan-out phase, Blackboard files are the seam). Claims the term "graph engineering", July 2026.
  **Not seen there, unverified after one read:** authority containment child ⊆ parent on an edge (`permissions: autonomous` is per agent, no edge check); a byte ceiling on the fixed prompt part (`max-tokens` is generation, metering is measured); a typed brief per edge (down-flow is `writes`/`reads` paths, only `outputs` is typed); round-trip fidelity with 700-line MDs (`prompt { }` is an inline block — does import inline the prose or point at it?). Scope is wide: `kitchen-sink.at` is 17 KB for one topology with providers, MCP, redis checkpoints, vector stores, registry, SOPS. We need a tenth of it.
- **Workflow tool, this harness** — `agent()` / `parallel()` / `pipeline()` scripts with phases, labels, schemas on handback. `claude-security:scan` is one. That script already _is_ structure-as-code: spawns, counts, contracts. **Decision for v1:** the spec targets MD-agent trees (claude-oss, Jimmy) where nothing declares structure. For a workflow-scripted tree the script is the source of truth and a JSON beside it would be a second copy; the reader should ingest the script instead. Not in v1. Second input format, after claude-oss round-trips.
- **claude-studio** (androidZzT, MIT) — DAG canvas for Claude Code agents, 4 edge types (dispatch / report / sync / roundtrip), writes `.claude/` files. One-way: no cost, no authority, no round-trip, no import. Repo answered 404 on 2026-09-19.
- **ccbuilder.dev**, **claude-subagent-editor** (2 stars) — canvas or form, zip export. Same limits.
- **Swarms Cloud Workflow Builder** — n8n-style DAG on their runtime. Vendor-bound.
- **Swarm Skills** (openJiuwen / Renmin Univ., arxiv 2605.10052, May 2026, read in full) — extends Anthropic Skills: `kind: swarm-skill`, `roles[]` in frontmatter, `roles/*.md`, `workflow.md` (mermaid in prose), `bind.md` (max_turns, max_tokens, gates, in prose), `evolutions.json` (self-patching, scored E·U·F). "A description format, not a runtime." JiuwenSwarm 6.5k stars. Explicitly omits isolation, message passing, enforcement. Edges are mermaid in prose, unparsed. One budget for the whole swarm. No contracts checked, no cost, no import, no validator. Evidence: crawled skill repos; no conformance test on any host, per their own Limitations.
- **AgentSpec** (ICSE 2026, arxiv 2503.18666) — DSL for runtime enforcement: trigger + predicate + enforce. Our doctor layer, formalized. No multi-agent composition.
- **Agent Behavioral Contracts** (arxiv 2602.22302) — pre/post conditions per agent, runtime checked. Our brief + handback, as contracts.
- **AUML** (FIPA/OMG, ~2000–2005) — UML extension for agent interaction protocols. Died with FIPA, never revived for LLM agents. Lifeline and multicast ideas worth keeping.
- **Pattern catalogs** (Anthropic, Google, AWS, arxiv 2405.10467) — vocabulary, no notation, no tooling.

After AgenTopology, what nobody is seen to have shrinks to: authority containment on edges, a prose byte budget, a typed brief per edge, and MD-by-path round-trip. Everything else on our list exists there. Two earlier rounds of search missed it; the third reviewer found it. Lesson: search by what the tool would call itself ("harness as code", "topology"), not by what we call it.

Cheap compatibility to keep: accept Swarm Skills' `kind:` and `roles[]` frontmatter so one of theirs loads into our catalogue; cite "coordination engineering" as their term.

## The AgenTopology trial

**AgenTopology 0.5.1 trialled on claude-oss, 2026-09-19. Failed on all three questions.** Scratch copies only, nothing written into claude-oss. Findings, in order met:
   - `import` walks the whole `--dir` including `.git/` and dies on `fsmonitor--daemon.ipc` (socket). Needs a copy without `.git`.
   - On the plugin layout (`agents/*.md`) it imports zero agents; only `commands/` and `skills/` are seen. Its importer matches `agents/<id>/AGENT.md` — its own scaffold layout — not `.claude/agents/<name>.md`, the documented Claude Code one. Round-trip is with its own output, not with the ecosystem.
   - After re-laying out to `agents/<id>/AGENT.md`: crash `items.map is not a function`. Its frontmatter parser only reads block lists (`- item`); `tools: Bash,TodoWrite,Skill,Agent` (the Claude Code form) and `tools: [a, b]` both become a string. Had to rewrite frontmatter to continue.
   - Then: 14 agents, frontmatter only. **The prose body is dropped entirely** — it reads only a `## Instructions` section, which no real agent MD has. `developer.md`'s 696 lines vanish; `info` then says "Agent has no prompt" fourteen times. Question (c): pointer nor inline — gone.
   - **The flow is fabricated.** With no `## Flow` bullet list in a SKILL.md (its own scaffold format again), it emits an alphabetical chain: `auditor -> developer -> doctor -> lane-report -> recon -> release-auditor -> releaser -> scheduler-step -> sub-manager -> ...`. Not one of those thirteen edges exists. `info` reports "Detected Patterns: pipeline". The visualizer draws it. Question (a): the picture answers "who does what" with a lie.
   - "Generated file passes all validation rules." V4 / V11 / V93 fire on nothing because the graph they validate was invented. Question (b): no.
     Verdict: the DSL, the 93 rules and the Workflow mapping doc are real and well thought out; the import path that would connect them to an existing MD-defined tree is not. Adopting means authoring `.at` by hand and moving prose into `prompt {}` blocks or their `## Instructions` convention — the same hand-authoring as our `swarm.json`, in their DSL, with their 90% we do not need. Not adopted. Keep it as the reference for what a validator list looks like (V11 especially) and revisit if `import` ever reads real agent files; open an upstream issue with the three repro steps.
